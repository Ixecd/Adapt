## 并发
- **并发(concurrency)**: 逻辑上具备同时处理多个任务的能力
- **并行(parallesim)**: 物理上在同一时刻执行多个并发任务

- **并行一定存在并发，并发不一定存在并行**

- **协程**: 在单线程上，多个协程并发执行
1. 协程的大小一般在2kb，栈的大小可以伸缩，过程是全拷贝
2. 协程栈空间的大小是有限制的，在 `src/runtime/stack.go` 中 maxstacksize = 1 << 20 也就是1MB，先给个1MB顶着，等runtime.main再设置真正的值
3. 在 `src/runtime/proc.go`中 根据机器的位数 64位 栈空间最大 1GB， 32位 栈空间最大250MB，实际上要更小一点，因为它用的是整数而不是位运算后的结果😂

## 任务
简单将 `goroutine` 归为协程(coroutine)并不合适。它类似多线程和协程的综合体，以最大限度发挥多核处理器能力，提升执行效率

- 按需扩张的极小初始栈，支持海量任务
- 高效无锁内存分配和复用，提升并发性能
- 调度器平衡任务队列，充分利用多处理器
- 现成自动休眠和唤醒，减少内核开销
- 基于信号(signal)实现抢占式任务调度

使用 `go` 关键字将目标函数和参数 打包(非执行)成并发任务单元，放入待运行队列，这里参数是立即计算并复制
无法确定执行时间、执行次序，以及执行线程，由调度器负责处理

所有用户代码都以 `goroutine` 执行，包括 `main.main` 入口函数。
进程结束，不会等待其他正在执行或未执行的任务。

## 等待
等待任务结束，可以更加优雅一点
- channel: 信号通知
- WaitGroup: 等待多个任务结束
- Context: 上下文通知
- Mutex: 锁阻塞
一次性通知行为，可使用空结构。只要关闭通道，等待（阻塞）即可解除
```go
func main() {
	q := make(chan struct{})

	go func() {
		defer close(q)
		println("done.")
	}
	// 阻塞等待
	<-q
}
```
协程同步
- 一个goroutine完成通知 -> close(done)
- N个goroutine等待完成 -> sync.WaitGroup
- 需要取消/超时/级联退出 -> context + WaitGroup
```go
func main() {
	var wg sync.WaitGroup
	wg.Add(10)

	go func() {
		defer wg.Done()
		fmt.Println("done.")
	}()

	wg.Wait()
}
```
sync.WaitGroup 和 信号量之间的关系

本质上 WaitGroup可以看作是一个**专用的计数信号量**，初始值为要等待的任务数(n)
- 每个任务完成时"释放1"
- 主线程“等待信号量归0”

对了，不要频繁调用 GOMAXPROCS，它会导致 STW(stop the world)，影响性能. GMP模型中 的 P 就是 GOMAXPROCS的 值，其不是一个轻量对象，它是runtime的地基
