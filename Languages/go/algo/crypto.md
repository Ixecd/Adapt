## crypto

### 对称加密

就是加密和解密用同一个密钥，加解密速度快，安全性得不到保证

常见的有 DES、3DES、Blowfish、RC5，IDEA等

**加密方式**
- ECB: 电子密码本模式
- CBC: 密码分组链接模式
- CFB: 加密反馈模式
- OFB: 输出反馈模式

### 非对称加密

就是加密和解密用不同的密钥，加解密速度慢，安全性得到保证。公钥和私钥是一对。如果用公钥加密，只有用对应的私钥才能解密

**机密信息交换基本过程**
- 甲方生成一对密钥，分发公钥
- 乙方用公钥加密，发送密文给甲方
- 甲方用私钥解密

保密性较好，算法复杂，安全性依赖于算法和密钥。

**加密方式**
- RSA: 非对称加密算法
- DSA: 数字签名算法
- ECC: 椭圆曲线加密算法

### 摘要算法
加密过程不需要密钥，并且加密数据无法解密。只有输入相同明文，经相同算法才能得到相同密文

不存在密钥管理与分发问题，适合于分布式网络上使用。无论输入消息有多长，计算出的摘要的长度是固定的

常见的摘要算法有 MD5、SHA-1、SHA-256、SHA-512等

### 数字证书
数字证书是一个经过 **证书授权中心** (CA) 数字签名，包含**公开密钥**和**拥有者信息**的文件

最简单的证书，包含公钥、名称，以及授权中心的数字签名。数字证书还有一个特性，有expire，在证书过期之前，证书都是有效的

数字证书是权威性电子文档，可由权威公正的第三方机构（CA）签发的证书，也可以由企业级CA系统进行签发。CA有自己的密钥对，并使用其对证书进行签名。用户使用CA公钥比对签名即可确认证书的合法性

**颁发过程**:
- 用户生成自己的密钥对，将公钥以及个人信息(CSR-Certificate Signing Request)发给认证中心
- 认证中心核实身份，确认请求确实由该用户发送。具体来说确认两件事情
	1. 申请者提供的身份信息是真实的
	2. 申请者确实拥有该公钥对应的私钥 -> 通过验证 CSR 的签名来确认
- CA使用自己的「CA 私钥」签发证书
	1. CA会创建一个 X.509数字证书，内容包含: 用户公钥、用户身份信息、证书有效期、证书用途、证书序列号、颁发者信息、其他扩展字段等
	2. 使用自己的CA私钥对证书进行数字签名，得到的就是最终的「数字证书」 注意: 签名证书使用的是CA的私钥，之后验证证书时用的是CA的公钥
	3. CA将签好的证书返回给用户，申请者保存**用户私钥**，**CA签发的数字证书（Cert）**，生成的证书只包含申请者的公钥，不包含申请者的私钥

**数字签名**

首先 **私钥加密** != **数字签名**

数字签名的流程为:
1. 对数据进行hash
2. 使用私钥对hash值进行签名
3. CA使用公钥验证签名与数据是否匹配

**CA验证CSR的步骤**
1. CA使用CSR中的公钥来签名证书
	- CSR提供**用户公钥（明文）**，**用户私钥对CSR数据的签名**
	- CA使用CSR内的公钥验证签名是否有效
2. 数字签名验证用的是数学「验证函数」，不是对数据的解密
3. 也就是说任何拿到CSR的人，理论上都可以验证CSR的签名

#### X.509
数字证书格式遵循X.509标准，由国际电信联盟(ITU-T)制定

- PEM: 文本格式
- DER: 二进制格式

自签名证书
```sh
# 1. 生成私钥
openssl genrsa -out my.key 1024

# 2. 生成证书申请文件 csr
openssl req -new -key my.key -out my.csr

# 3. 用私钥对证书申请进行签名，生成证书
openssl x509 -req -in my.csr -out my.crt -signkey my.key -days 365
```
