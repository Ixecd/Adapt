## 门控时钟与数据-时钟对齐

### 门控时钟：时钟不是一直给，按需放行

```verilog
assign gclk = clk & en;   // 门控：en=1 放行时钟，en=0 挡住
// 模块用 gclk，en=1 才有时钟（才工作）
```

- **时钟源常驻**（晶振/PLL 一直跑），门控只控制"传不传"到某模块——不是"想有时钟就有"，是"想用才放行"
- 意义：**省电**——模块不用时不给时钟 → 不翻转 → 省动态功耗（穿戴/IoT 续航命脉）
- 你 Feelings：通信/刺激时才开时钟，平时关 → 延长续航
- 坑：门控时钟有毛刺/边沿畸变风险，常用"时钟使能（clock enable）"替代（时钟常跑但逻辑不动作，更安全）

### 数据与时钟对齐：一拍一数据

```
同步设计：时钟是"节拍器"，数据是"每拍内容"
  发方：每个时钟沿放一个数据（数据跟着沿走）
  收方：每个时钟沿采一个数据（沿来时采当前数据）
→ N 个数据 = N 个时钟沿 = N 拍（一拍一数据）
→ "送几个数字就几个时钟"成立，但本质是"一拍一数据，时钟是拍"
```

- 不是"数据来几个就强行给几个时钟"，是**时钟常跑（节拍），数据一拍一个对齐**
- 门控时钟（省电）是"没数据时可停时钟"，有数据时仍"一拍一数据"
- 呼应"带时钟的 DP"：每拍迭代一次，几份数据迭代几次

**一句话**：时钟源常驻、门控按需放行（省电）；时钟是采样节拍、数据一拍一对齐——数据量自然对应时钟沿数。
