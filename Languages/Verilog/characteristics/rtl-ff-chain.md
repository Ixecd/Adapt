## 数据依赖决定触发器串联（RTL 本质）

Verilog 可综合代码描述的**就是真实硬件**——`<=` 级联写出的就是串联的 D 触发器。

### 编写顺序 → 触发器排列

```verilog
begin
    out1 <= din;    // 触发器1：D=din → Q=out1
    out2 <= out1;   // 触发器2：D=out1 → Q=out2
end
```

综合出的硬件：
```
din ──→ [D触发器1] ──Q──→ out1 ──→ [D触发器2] ──Q──→ out2
               ↑                      ↑
             clk                    clk
```

- 两个触发器**串联**，out1 是中间节点
- 这就是"打两拍" / 移位寄存器：数据延迟两拍

### 决定排列的是"数据依赖"，不是"语句行号"

```verilog
// 顺序写反，综合结果一样（<= 并行、顺序无关）
begin
    out2 <= out1;   // out2 依赖 out1，物理上 out1 必须在前面
    out1 <= din;
end
// 硬件排列不变：din→FF1→out1→FF2→out2
```

- **数据流依赖（谁驱动谁）决定物理连接**，语句行号不影响综合结果
- 顺序影响的是**仿真的采样时刻**（写反仿真会错），不影响硬件排列

### 为什么是"延迟一拍"：沿前采样

```verilog
always @(posedge clk) begin
    out1 <= din;    // 预定：本沿结束时 out1=din
    out2 <= out1;   // 预定：out2 = "本沿采样瞬间的 out1"
end
```

**关键机制**：仿真器在"沿"这个时刻点，**先采样所有右边（沿前值），再提交所有左边**：
- 采样瞬间，out1 还是**旧值**（还没更新）
- 所以 out2 拿到的是 **out1 沿前值** = **out1 上一拍的值**
- 这是**确定性**的（不是概率 1/2），`<=` 的规则就是"右边永远采样沿前值"

```
沿1: out2 = out1初始值
沿2: out2 = 沿1的din
沿3: out2 = 沿2的din2
→ out2 稳定落后 out1 一拍 → 确定性的延迟一拍
```

**一句话**：`out2 <= out1; out1 <= din` 综合成两个串联 D 触发器（数据依赖决定排列，不是语句顺序）；out2 取值瞬间 out1 还是沿前旧值，所以 out2 确定性地延迟一拍。这正是打两拍/移位寄存器的本质。
