## module 与端口

模块是 Verilog 的基本单元，类似 Go 里的 package + func 组合。端口分 input/output/inout。

```verilog
module counter #(parameter W = 8) (
    input  wire       clk,    // 时钟
    input  wire       rst_n,  // 低有效复位
    output reg [W-1:0] cnt    // 计数值，reg 类型（always 块里赋值）
);

    always @(posedge clk or negedge rst_n) begin
        if (!rst_n)
            cnt <= 0;
        else
            cnt <= cnt + 1'b1;
    end

endmodule
```

- `wire`：组合逻辑连线，`assign` 赋值；`reg`：时序逻辑变量，`always` 块里赋值
- 参数化 `#(parameter W = 8)` 类似模板/泛型，实例化时可覆盖 `counter #(.W(16)) u(...)`

## 数据类型

```verilog
wire        a;          // 1 bit 线网
wire [7:0]  bus;        // 8 bit 总线
reg         r;          // 1 bit 寄存器
reg [31:0]  data;       // 32 bit 寄存器
integer     i;          // 整型（多用于 for 循环/仿真）
parameter   W = 8;      // 常量，类似 const
localparam  W2 = W * 2; // 局部常量，不可被外部覆盖
```

- 位宽用 `[MSB:LSB]` 表示，如 `[7:0]` 是低 8 位

### 数值写法：位宽 ' 进制 数值

格式 = `位宽 ' 进制 数值`：前面是位宽（用几位二进制表示），`'` 分隔，中间 b/d/o/h 是进制，后面是在该位宽下的具体数值。

```
4'b0100     // 位宽4，二进制0100 = 十进制4（位宽数字和数值数字只是碰巧相等）
4'b0101     // 位宽4，数值5（5≠4，位宽和数值无关）
8'd255      // 位宽8，十进制255 = 二进制11111111
8'ha5       // 位宽8，十六进制a5 = 十进制165
1'b1        // 1位二进制存"1"（不写位宽会被当32位整数）
```

- 进制标记：`b`二进制 / `o`八进制 / `d`十进制 / `h`十六进制
- 同一位宽可换进制等价写：`4'd10 == 4'b1010 == 4'ha`（都是 10）
- 位宽是"盒子大小"（能表示 0~2^n-1），数值是"盒子里装的东西"，两者数字无关

### 位宽不够会静默截断

数值超出位宽能表示的范围 → 只留低 n 位，不报错（仿真和实物都对不上，隐蔽坑）：

```
4'd15     // OK: 15 = 1111（满值）
4'd16     // 问题: 16 = 10000（5位）→ 截断为 0000 = 0
8'd255    // OK: 255 = 11111111（8位满值）
8'd256    // 问题: 256 超出 → 截断为 0
```

### reg 的位宽索引：[3:0] vs [8:1]

位宽都是"几位"，区别只在 LSB 从几开始：

```verilog
reg [3:0] b;    // 4位: b[3] b[2] b[1] b[0]，b[0]是LSB
reg [8:1] c;    // 8位: c[8] c[7] ... c[1]，c[1]是LSB（少见，为对齐datasheet位号）
reg [1:8] d;    // 小端写法，位序反转，赋值会反转字节序（避免用）
```

惯例是 `[N-1:0]`（LSB 从 0 开始）。`[8:1]` 里的 1 是 LSB 位置，不是特殊符号。

### 负数存补码 + signed 关键字

reg 默认无符号（全部当正数）。存负数 = 存补码，且要靠 signed 才能正确解释：

```verilog
reg [3:0] a;
a = -1;          // 存 4'b1111（-1 补码）

reg signed [3:0] s;
s = -2;          // s = 4'b1110，值 = -2
```

**补码算法**：`-N = 2^位宽 - N`（或取反+1）
```
-2 → 16-2 = 14 = 1110；取反+1：0010→1101→1110
```

**signed 的含义 = 最高位当符号位，不是"默认负数"**：
```
无 signed:  全部正数（0 ~ 2^n-1）
有 signed:  看最高位(MSB)
  MSB=0 → 正数（和 unsigned 完全一样）
  MSB=1 → 负数（补码解读）
4'b0111: unsigned=7,  signed=7   （MSB=0 一致）
4'b1110: unsigned=14, signed=-2  （MSB=1 分叉）
```

**同一个位模式，两种读法，区分靠声明**（和 C 的 int8_t/uint8_t 同理）：
- 声明 signed → 算术/比较/符号扩展全走补码规则
- 位扩展：无符号零扩展（填0），有符号符号扩展（填MSB）
- 4 位补码范围 -8~+7；负数最高位一定是 1

**软件人必踩坑**：Verilog 的 reg 默认无符号，没加 signed 就做负数运算结果全错——和软件 int 天生有符号相反。UART 收发字节/任何协议处理都离不开这套。

## assign 连续赋值

`assign` 是组合逻辑，等号右侧变化立即反映到左侧，类似 wire 的"接线"。

```verilog
wire a, b;
wire y;

assign y = a & b;   // 与门
assign y = ~a;      // 非门
assign y = a | b;   // 或门
assign y = a ^ b;   // 异或
```

### 显式连续赋值（先声明 wire 再 assign）

先 `wire` 声明线网，再单独 `assign` 赋值。**显式 wire 的用武之地是"内部信号"**——端口（input/output）默认就是 wire，不用重复声明。

```verilog
module example_assignment (
    input  [3:0] a, b,      // 端口：外部输入（默认 wire，不用再声明）
    output [3:0] c, y       // 端口：外部输出
);

wire [3:0] m, n;            // 内部信号，必须显式 wire ← 显式的核心

assign y = m | n;           // 显式连续赋值
assign #(3, 2, 4) c = a & b; // 显式 + 延时赋值

endmodule
```

**常见错误**：端口列表和 input/output 声明不一致（m,n 悬空）、`input`/`wire` 拼错（`inpui`/`wirc`）、`[3;0]` 分号写成冒号。

### 延时赋值 #(rise, fall, turnoff)

```verilog
assign #(3, 2, 4) c = a & b;
```

三个数含义（**仿真用**，综合时忽略）：
```
#(rise, fall, turnoff)
    ↑3     ↑2     ↑4
 上升延时  下降延时  高阻延时(只有三态输出才有意义)
```

- c 从 0→1 延迟 3 个时间单位，1→0 延迟 2 个
- 建模门传播延迟（仿真看时序），综合不认精确门延时

### assign 顺序无关：全是并行接线

`assign` 是声明"持续接线"，不是"执行指令"——两条 assign 互换顺序，结果完全一样：

```verilog
// 顺序A
assign y = m | n;
assign #(3,2,4) c = a & b;

// 顺序B（互换，等价）
assign #(3,2,4) c = a & b;
assign y = m | n;
```

**和软件的本质区别**：
```
软件（C/Go）: 语句顺序重要。a=1; b=a; → b=1；若 b=a; a=1; → b=旧值
Verilog assign: 顺序无关，都是"持续接线"，结果一样
```

- assign 是"持续赋值"：从仿真开始到结束，`y` 始终等于 `m|n`——不是"某时刻执行一次"，是**永远生效的连线**
- 并行性规则：
  ```
  assign 之间：可互换（并行，持续连线）
  always 之间：可互换（并行）
  always 内部：顺序重要（语句有先后，见阻塞/非阻塞）
  ```

**新手最常卡的点**：用软件思维以为 assign 按顺序执行。实际 module 内部所有 assign/always 都是**并行的**，只有 always 块**内部**语句才有顺序概念。

## always 块

`always` 是最核心的块，分组合（电平敏感）和时序（边沿敏感）两种。

### 语法格式与敏感事件列表

```verilog
always @(敏感事件列表)
    语句;                     // 单条语句不用 begin-end

always @(敏感事件列表) begin
    多条语句;                 // 多条必须 begin-end 包起来
end
```

**敏感事件列表的类型**：
```verilog
// 单个信号（电平敏感，组合逻辑）
always @(a)                  // a 变化就触发
always @*                    // 所有输入变化都触发（最常用，自动包含）

// 多信号
always @(a or b)             // a 或 b 变化都触发
always @(a, b)               // 逗号写法等价
always @*                    // 等价"所有用到的信号"

// 边沿（时序逻辑）
always @(posedge clk)        // 时钟上升沿
always @(negedge clk)        // 时钟下降沿

// 混合（时钟 + 异步复位，常用）
always @(posedge clk or negedge rst_n)   // 异步复位低有效
always @(posedge clk or posedge rst)     // 异步复位高有效
```

**电平敏感 vs 边沿敏感决定电路类型**：
```
@(a) 或 @*           → 组合逻辑（a 变就响应，无记忆）
@(posedge clk)       → 时序逻辑（触发器，只在上升沿锁存）
@(posedge clk or negedge rst_n) → 时序 + 异步复位
```

**易错点**：`@*` 自动包含"块内所有用到的信号"，不用手动列——列漏一个信号 = 仿真不更新（经典 bug：`@(a)` 漏掉 b）。

**为什么敏感列表不写表达式（& | ^ 只进块内）**：
- 电路只能感知"**输入信号变没变**"（a、b 各自），判断不了"**表达式结果变没变**"（a&b 结果）
- 真实硬件里 `a&b` 是个与门，a 或 b 任一变化输出立即跟随——电路没有"结果变化检测器"，只有"输入变化检测器"
- 所以 `@(a & b)` 综合后实际是"a 或 b 变化就触发"（跟 `@(a or b)` 一样），但**容易误导 + 漏信号**（还有 c 时 c 变不触发）
- `& | ^` 运算符用在**块内**做运算（数字电路能力）；敏感列表只负责"哪个输入变了要触发"（电路感知能力）——两者分工不同

```verilog
always @(a & b) begin    // 只 a,b 触发，c 变不触发 → bug
    y = a & b | c;
end

always @* begin          // 自动列全 a,b,c，物理正确
    y = a & b | c;
end
```

**避坑：电平 + 边沿别混在一个 always 里**

`@(a or posedge clk)` 语法合法，但**别写**——把"电平触发（组合）"和"边沿触发（时序）"混一个 always，综合工具会警告/乱综合：

```verilog
// 坑：混用
always @(a or posedge clk) begin
    q <= d;      // 触发器（边沿）
    y = q & a;   // 组合（电平）
end
```

**正确做法**：一个 always 只做一种逻辑，触发器 + 逻辑门拆开：

```verilog
reg q;
wire y;

always @(posedge clk)      // 触发器：只边沿敏感
    q <= d;

assign y = q & a;          // 逻辑门：assign，a 变就响应
```

**铁律**：一个 always 里**要么全电平（组合）、要么全边沿（时序）**，别混。需要"触发器 + 逻辑门"电路 → 拆成 `always @(posedge clk)` 做触发器 + `assign`/`@*` 做逻辑门，各司其职。

### 组合逻辑（电平敏感 @*）

```verilog
// @* 表示"所有输入变化都触发"，不用手动列端口
reg [3:0] y;
always @* begin
    case (sel)
        2'd0: y = 4'b0001;
        2'd1: y = 4'b0010;
        default: y = 4'b0000;
    endcase
end
```

### 时序逻辑（边沿敏感 posedge/negedge）

```verilog
reg [3:0] q;
always @(posedge clk or negedge rst_n) begin
    if (!rst_n)
        q <= 4'd0;
    else
        q <= d;   // 在时钟上升沿采样
end
```

**if-else 顺序 = 硬件优先级**：
```
if (!rst_n)   → 复位最高优先级（异步复位，无条件优先）
else          → 时钟采样（复位没发生时，时钟沿才采样数据）
```

- 复位必须放 if（优先）——异步复位不管时钟，一变就强制复位
- 时钟采样放 else——复位没发生时，时钟沿才锁存数据
- 写反 = 复位优先级错 = 硬件行为错
- 敏感列表 `negedge rst_n`（异步复位）和 `posedge clk` 是"或"关系触发，唤醒后 if-else 决定这次干嘛：
  ```
  rst_n 下降沿唤醒 → if (!rst_n) 真 → 复位
  clk 上升沿唤醒  → if (!rst_n) 假 → else → 采样
  ```

### 异步清零 vs 同步清零（就差敏感列表）

**本质：异步把复位信号加进敏感列表，同步不加。逻辑代码一模一样，就差敏感列表里有没有 rst_n。**

```verilog
// 异步清零：rst_n 在敏感列表 → 一变就触发 → 立刻清零（不依赖时钟）
always @(posedge clk or negedge rst_n)
    if (!rst_n) q <= 0;
    else        q <= d;

// 同步清零：rst_n 不在敏感列表 → 只有 clk 唤醒 → 等沿才检查清零
always @(posedge clk)
    if (!rst_n) q <= 0;
    else        q <= d;
```

| | 异步清零 | 同步清零 |
|--|---------|---------|
| 触发 | 复位信号一变就清零 | 等时钟沿才清零 |
| 敏感列表 | 含 `negedge rst_n` | 只有 `posedge clk` |
| 依赖时钟 | 否（随时） | 是（等沿） |
| 优点 | 响应快，上电立刻锁已知态 | 时序干净，抗毛刺 |
| 缺点 | 复位毛刺会误触发 | 复位要等沿，稍慢 |

- FPGA 触发器原生支持异步复位（SET/CLR 引脚），不额外占资源，上电时钟未稳定也能立刻复位——所以常用异步
- 同步复位时序统一（和正常逻辑一样等沿），抗复位线毛刺，但复位要等时钟沿

### 异步为何逐步被同步取代

不是异步烂，是系统越复杂，异步的"不可预测性"撑不住：

1. **可分析性**：同步全局同一时钟沿采样，时序可预测、可仿真、可验证；异步事件随时来，难分析难收敛
2. **毛刺敏感**：异步复位线上一个毛刺就误触发复位；同步要等时钟沿判断，毛刺过不去
3. **可移植复用**：同步所有工具/库/标准统一支持；异步换个工艺/频率可能出问题
4. **复位释放竞争（异步天生 bug）**：复位信号释放（rst_n 变高）和时钟沿重叠 → 亚稳态 → 部分触发器复位部分没有 → 系统不一致。同步没这问题
5. **工具链成熟**：现代工具对同步优化充分，异步支持弱

**但没彻底淘汰**：上电立刻锁态、FPGA 原生支持仍是异步价值。工业界流行**混合方案**：

```verilog
// 异步断言 + 同步释放（两全其美）
// 复位有效立刻生效（异步），释放时和时钟对齐（同步，避免竞争）
```

本质：**复杂度倒逼可预测性**——同步"全局统一时刻"更好分析，所以逐步主导；异步靠"异步断言+同步释放"保留价值。

## 阻塞赋值 = 与非阻塞赋值 <=

这是 Verilog 最容易踩的坑，相当于"单线程顺序" vs "并行同时"。

```verilog
// 阻塞赋值 =：顺序执行（类似普通赋值），用于组合逻辑
always @* begin
    a = b;
    c = a;   // c 拿到的是 b（已经更新）
end

// 非阻塞赋值 <=：并行执行（所有右侧同时采样），用于时序逻辑
always @(posedge clk) begin
    a <= b;
    c <= a;   // c 拿到的是 a 的旧值（采样瞬间的值），不是 b
end
```

**铁律**：时序逻辑用 `<=`，组合逻辑用 `=`。混用会导致仿真和综合结果不一致。

### 同一个 `<=`：赋值 vs 比较，看位置

`<=` 有两种身份，靠"是不是一条完整赋值语句"区分：

```
赋值语句（非阻塞）: a <= 1;       // a 在左边，1 是值，分号结尾 → 把 1 赋给 a
关系运算（比较）:   if (a <= 5)   // a 和 5 比大小，结果被 if 用 → a 小于等于 5？
```

```verilog
// 赋值：always 块里，左边是变量，右边是值，独立语句
always @(posedge clk) begin
    a <= 1;       // 非阻塞赋值：把 1 存进 a
    b <= a;       // b 拿 a 旧值（同一沿并行采样）
end

// 比较：作为表达式的一部分
x = (a <= 5);     // 这里 a<=5 是关系比较，结果 0/1 赋给 x
if (a <= 5) ...   // 还是比较
```

**判断准则**（比"看分号"更准）：
- `<=` **左边是赋值目标变量、右边是值、整句就是"变量=值"** → 非阻塞赋值
- `<=` 左右都在表达式里，结果被 if/case/assign 使用 → 关系比较

**坑**：分号是语句结束符不是赋值标志。`if (a <= 5)` 整个 if 语句后面也有分号，但那个 `<=` 还是比较。**看左边是不是被赋值的变量名**才是定盘星。

### 语句延时 #100：仿真用，非阻塞并行 / 阻塞串行

`#100` = 等 100 个仿真时间单位，**不可综合，只能仿真/testbench 用**（硬件没有"抽象时间"，只有"时钟沿"，真延迟靠计数器数时钟）。

**非阻塞 `<=`：四条同时延迟**（并行）：
```verilog
always begin
    a <= #100 1;   // 四条同时等100
    b <= #100 2;
    c <= #100 3;
    d <= #100 4;   // 总延迟 100，四条一起更新
end
```

**阻塞 `=`：依次延迟**（串行累加）：
```verilog
always begin
    a = #100 1;    // 等100
    b = #100 2;    // 再等100 → 200
    c = #100 3;    // → 300
    d = #100 4;    // → 400（总延迟 400）
end
```

**为什么**：
```
非阻塞 <=：所有右边"同时采样+同时预定"，延迟也同时 → 总延迟 100
阻塞 =：一条条执行，每条延迟累加 → 总延迟 400
```

**注意**：非阻塞每条延迟不同则各自生效（a 100、b 200 更新），互不等；一样的 #100 就是同时。呼应"非阻塞并行采样"——延迟也是并行的。

**可用场景**（全在 testbench）：`#5 clk=0; forever #5 clk=~clk` 生成时钟、`#20 rst_n=1` 注入复位、激励延时。**DUT 可综合代码里不能有 `#`**。

## 参数与实例化

```verilog
// 定义
module mux2 #(parameter W = 8) (
    input  [W-1:0] a, b,
    input          sel,
    output [W-1:0] y
);
    assign y = sel ? a : b;
endmodule

// 实例化（类似调用）
wire [15:0] ya, yb;
wire        s;
wire [15:0] y16;

mux2 #(.W(16)) u_mux (
    .a(ya), .b(yb), .sel(s), .y(y16)
);
```

- `.name(port)` 是**按名字连接**，比按位置安全，类似 Go 的命名参数/结构体字段
- `#(.W(16))` 覆盖默认参数，类似泛型实例化

### 参数覆盖：能指定是因为有默认值

**"凭啥能指定 or_delay"——因为它声明了 `parameter or_delay = 1`（有默认值）**：
```verilog
module fulladder(...);
    parameter or_delay = 1;    // 默认值在这
    ...
endmodule

fulladder #(.or_delay(5)) U2(...);   // 覆盖默认值 1 → 5
```

**规则**：
- 能覆盖的前提：子模块里声明了 `parameter`（有默认值）
- **"不在同一个模块"完全可以指定**——这就是参数化的意义：定义带默认值，任何地方实例化都能覆盖
- 但不能指定"子模块没声明的参数"（那是不存在，不是覆盖，报错）
- 类比 C++：`int add(int a, int b = 1)`，调用 `add(5, 10)` 覆盖 b——因为 b 声明了默认值

### 参数设置的三种方式（由浅到深）

```verilog
// 1. 默认值（模块内声明）
module fulladder(...);
    parameter or_delay = 1;

// 2. 实例化覆盖（本层参数）
fulladder #(.or_delay(5)) U2(...);

// 3. defparam 深层覆盖（层级路径，旧写法）
defparam U2.U1.xor_delay = 6;   // fulladder U2 里半加器 U1 的 xor_delay
fulladder U2(...);
```
- `#(.or_delay(5))` 只能覆盖"本层参数"（fulladder 自己的）
- `defparam` 能深入嵌套改参数（`U2.U1.xor_delay`），但旧、可读性差，现代推荐 `#()`（深层的用实例化逐层传）

**为什么不用 defparam（推荐 `#()` 覆盖）**：
```
defparam 的问题：
  1. 参数被"埋在"代码里到处改 → 读代码不知道参数哪来的（可读性差）
  2. 综合工具支持不一 → 可移植性差（有些综合器不支持/警告）
  3. 改了哪一层要靠"层级路径"猜 → 维护难（改模块结构就失效）
推荐做法：
  用实例化覆盖 #(.param(value))——参数在"实例化处"一目了然
  深层参数 → 让子模块用 parameter 显式传下去（层层声明，别用 defparam 跳层改）
→ 一句话：defparam 是旧时代的"跳层魔法"，可读性/可移植性差；
  现代用 #() 在实例化处显式覆盖，深层靠 parameter 逐层传递
```

**注意**：`defparam` 语法上每条都要 `defparam` 开头（`defparam U2.U1.xor_delay=6;` 每条都要写全），不能省略——否则编译报错。


### # 与 . 的区别（命名参数）

```verilog
fulladder #(.or_delay(5)) U2(...);
// #(...)     = 参数区标记（"这里是参数列表"）
// .名字(值)  = 命名参数（"or_delay 这个参数 = 5"）
```

- `#` 和 `.` 是两个独立语法：`#` 管"这是参数"，`.` 管"按名字指定"
- `.or_delay(5)` = 命名参数（指名道姓），`#(5)` = 按位置（第1个参数）
- 推荐命名参数：可读性好、不怕顺序变（类似 C++ 指定参数名 / Go 结构体字段）

**本质：`#(...)` 是"参数列表"容器，里面的 `.param(value)` 才真正赋值**：
```verilog
fulladder #(.or_delay(5)) U2(...);
//        └─────┬────┘
//   #(...) 参数列表标记（壳）
//         └──────┬──────┘
//   .or_delay(5) 给 or_delay 参数赋 5（肉）
```
- `#` 管"这是参数区"（容器），`.名字(值)` 管"给哪个参数赋什么值"（内容）
- 和端口连接同一个结构：`.p(sig)` = 给端口连信号，`.param(value)` = 给参数赋值
- 区别：参数列表传"值"，端口列表传"信号"


## 运算符

### 连接操作符 {}

把多个信号/常量按位拼接成更宽的向量（类似 Go 里多个值拼成一个 slice/结构体，但这里是按位拼）：

```verilog
wire [3:0] a = 4'b1010;
wire [1:0] b = 2'b11;
wire [5:0] c;

assign c = {a, b};        // c = 6'b101011（a 接 b）
assign c = {2'b01, a[1:0]}; // 混合常量+信号位
```

- 拼接后的位宽 = 各段位宽之和
- 括号里每一项可以是信号、常量、位选/段选

### 复制操作符 {{}}

把某个值重复 N 次拼接，**必须和连接操作符配合**（外层 `{N{...}}`）：

```verilog
wire [7:0] d;
assign d = {8{1'b0}};     // 8 个 0 → 8'b00000000（清零）
assign d = {4{2'b10}};    // 4 次重复 2'b10 → 8'b10101010

// 符号扩展的经典用法：
wire signed [3:0] s = 4'b1110;   // -2
wire [7:0] ext = {{4{s[3]}}, s};  // 复制符号位4次 + 原值 → 8'b1111_1110（-2 正确扩展）
```

- 复制次数必须是常量（综合期确定，不能是变量）
- `{4{2'b10}}` = 4 份 `10` 拼接 = 8 位

### 逻辑运算符 && || !（结果 1 bit）

作用在"整个值"上（非按位），结果只有 1 bit（0/1），类似 C 的真值判断：

```verilog
wire [3:0] a = 4'b0101;
wire [3:0] b = 4'b0000;

a && b      // 0（a非零=真, b为零=假, 真&&假=假）
a || b      // 1（真||假=真）
!a          // 0（a非零=真, 非真=假）
```

### 按位运算符 & | ^ ~（结果按位）

作用在每一位上，位宽不变（和逻辑运算符区分开）：

```verilog
wire [3:0] a = 4'b1010;
wire [3:0] b = 4'b1100;

a & b      // 4'b1000（逐位与）
a | b      // 4'b1110（逐位或）
a ^ b      // 4'b0110（逐位异或）
~a         // 4'b0101（逐位取反）

// 单目（归约）用法：结果 1 bit
&a         // 1（所有位都是1？1010有0 → 0）
|a         // 1（有任一1？有 → 1）
^a         // 0（奇偶校验：1的个数奇偶）
```

### 逻辑 vs 按位（易混点）

```verilog
a = 4'b1010; b = 4'b0100;
a & b    // 4'b0000（按位）
a && b   // 1（逻辑：a非零真, b非零真, 真&&真=真）
```

**关键区别**：`&&`/`||`/`!` 看"整个值是否为真"（非零即真），结果 1 bit；`&`/`|`/`^`/`~` 逐位算，结果同宽。写条件判断用逻辑运算符，算数据用按位运算符。

## 三种建模：行为级 / 数据流 / 结构性

同一个电路三种抽象层次（从抽象到具体），实际开发三者混合用。

### 行为级建模 Behavioral —— 最抽象，像写软件

用 `always` + if/case 描述"行为"，不关心电路长啥样：

```verilog
// 行为级：描述"计数行为"，不关心用几个加法器/触发器
always @(posedge clk or negedge rst_n) begin
    if (!rst_n) cnt <= 0;
    else if (en) cnt <= cnt + 1;
end
```

- 最接近高级语言（if/else/循环），综合工具负责翻译成电路
- 三段式状态机就是行为级

### 数据流建模 Dataflow —— 中间层，描述数据流动

用 `assign` + 运算符，描述"信号怎么算出来"：

```verilog
// 数据流：用表达式描述数据关系，不管内部结构
assign y = (a & b) | (c & d);
assign sum = a + b;
```

- 连续赋值，数据从输入流到输出，综合时把表达式变门电路

### 结构性建模 Structural —— 最具体，描述器件互连

用模块实例化，描述"哪些器件/门怎么连"：

```verilog
// 结构性：直接例化门电路，说清每个门接哪
and g1(y, a, b);      // 与门 g1: y = a & b
or  g2(z, y, c);      // 或门 g2: z = y | c
```

- 像画电路图：每个实例是芯片，端口是引脚
- 大设计 = 大量模块实例拼起来（顶层往往就是例化一堆子模块）

### 同一个电路三种写法（y = a&b | c&d）

```verilog
// 行为级：
always @* y = (a & b) | (c & d);
// 数据流：
assign y = (a & b) | (c & d);
// 结构性：
and g1(t1, a, b);
and g2(t2, c, d);
or  g3(y, t1, t2);
```

### 实际开发怎么用（老师强调的点）

**系统层面以结构性/数据流为主，行为级用在模块内部（局部）**：

```
结构性/数据流 = 顶层拼装、模块间连线（架构层，主流）
行为级        = 每个子模块内部逻辑（叶节点，局部）
```

- 复杂系统 = 顶层例化一堆子模块（结构性）+ 模块间 assign 连线（数据流）+ 每个模块内部 always/状态机（行为级）
- 不是"行为级不常用"，是"行为级用在最内层，外层靠结构拼"
- 对应软件："架构层拼模块（结构性），模块内写实现（行为级）"——结构性是架构，行为级是实现

## for 循环（综合 vs 软件的天壤之别）

**综合器把 for 当"复制电路"，不是"循环执行"**：
```
软件 for：运行时循环（执行 N 次）
硬件 for：编译时展开（循环体复制 N 份电路）
→ for(i=0;i<8;i++) → 综合成 8 份同样的电路
```

```verilog
// 推荐：常量次数 + 组合批量处理（综合时展开 8 份，省代码）
integer i;
reg parity;
always @* begin
    for (i = 0; i < 8; i = i + 1)
        parity = parity ^ bus[i];   // 8 份异或电路
end

// 不推荐：时序里 for / 变量次数（不可综合 / 语义错）
always @(posedge clk) begin
    for (i = 0; i < n; i = i + 1)   // n 是变量 → 不可综合！
        ...
end
```

**规则**：
- 循环次数必须**编译时确定**（常量 8/16），不能用运行时变量
- 每份循环体生成真实电路 → **循环多 = 电路爆炸**（面积大）
- 推荐：常量次数 + 组合逻辑批量处理（bus[i] 逐位）、`generate for`（批量例化模块，正规常用）
- 别用：变量次数（不可综合）、想表达时序状态（语义错）、大循环（电路爆炸）

**一句话**：for 是"复制电路"不是"循环执行"——次数必须编译时定，批量组合可以用（省代码），变量次数/时序状态/大循环别用。

## 结构性建模实例化：并行电路，不是串行执行

```verilog
// 全加器 = 2 个半加器 + 1 个或门（经典结构性建模）
module fulladder(p, q, ci, co, sum);
    input p, q, ci;
    output co, sum;
    parameter or_delay = 1;
    wire w1, w2, w3;

    halfadder U1(p, q, w1, w2);      // 半加器1：w1=p^q, w2=p&q
    halfadder U2(ci, w1, sum, w3);   // 半加器2：sum=ci^w1, w3=ci&w1
    or #or_delay U3(co, w2, w3);     // 或门：co = w2|w3 = (p&q)|(ci&(p^q))
endmodule
```

**关键：不能用串行眼光看这个代码**：
- 不是"先 U1 再 U2 再 U3"——是**三个电路同时存在、并行工作**（加电全开）
- 数据从 U1/U2 输出**流到** U3，不是"执行完 U1 才执行 U2"
- 结构性建模描述的是**电路连接图**，不是执行顺序——像"接线图"不像"指令序列"
- 和软件"从上到下执行"完全不同，module 内部实例全并行

## 门原语 gate primitive

**Verilog 语言自带的"门"，不用自己定义 module**：
```verilog
and / or / nand / nor / xor / xnor / not / buf / ...
```

```verilog
// 内置门实例化语法：门类型 #延时 实例名(输出, 输入1, 输入2, ...);
or #or_delay U3(co, w2, w3);
//  or        = 内置或门（语言自带，像关键字）
//  #or_delay = 门的传播延迟（parameter 设的数字，仿真用，综合忽略）
//  U3        = 实例名（随便起）
//  co        = 输出（第一个端口永远是输出）
//  w2, w3    = 输入
//  功能：co = w2 | w3
```

- `#or_delay` **不是模块名**，是"给这个门设的延迟属性"（就是个数字）
- `halfadder` 是你自定义的模块，`or` 是语言内置的门——两类不同，调用语法相同
- `#延时` 仿真才生效，综合时忽略（真实门延迟由物理决定）

### 内置基本元件：26 个（14 门级 + 12 开关级）

Verilog 语言内置 26 个基本元件（gate primitive / switch primitive），不用定义直接用。

**14 个门级元件**：
```
基本门（8）：
  and / or / nand / nor / xor / xnor   6 个多输入门
  not / buf                              2 个单输入缓冲/反相
三态门（4）：
  bufif0 / bufif1   高电平/低电平使能的缓冲（三态，含控制端）
  notif0 / notif1   高电平/低电平使能的反相（三态）
上拉/下拉（2）：
  pullup / pulldown   上拉/下拉电阻（把节点拉到高/低）
```

**12 个开关级元件（MOS 开关，晶体管级）**：
```
无控制开关（4）：
  tran / tranif0 / tranif1 / rtran    双向传输门
  rtranif0 / rtranif1                 电阻型传输门（带控制）
MOS 开关（4）：
  nmos / pmos / cmos / rnmos / rpmos / rcmos    NMOS/PMOS/CMOS 开关
```
（开关级 = 晶体管层建模，仿真/模拟用，综合一般不用）

**使用**：
```verilog
and g1(y, a, b);          // 与门
bufif1 g2(bus, data, en); // 三态缓冲：en=1 时 data→bus，否则高阻
pullup g3(pin);           // 上拉电阻：pin 默认拉高
nmos g4(out, in, ctrl);   // NMOS 开关：ctrl=1 导通
```

**一句话**：Verilog 内置 26 个基本元件——**14 个门级**（基本门 and/or/not 等 + 三态门 bufif/notif + 上拉/下拉 pullup/pulldown）+ **12 个开关级**（双向传输门 tran 系列 + MOS 开关 nmos/pmos/cmos）。门级可综合常用，开关级是晶体管层建模（仿真/模拟用）。
