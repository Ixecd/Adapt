## concurrency/ 并行与跨时钟域（预留位）

这是软件人最容易忽略、但 FPGA 最容易翻车的部分。对应 Go 的 concurrency。

### always 块并行
多个 always 块物理并行，没有"顺序"概念（和 goroutine 本质区别：硬件真并行，软件靠调度）。

### 跨时钟域 CDC
```
- 慢→快：打两拍同步（两级寄存器）
- 快→慢：握手 / FIFO
- 单 bit 信号：双触发器同步器
- 多 bit 信号：异步 FIFO / 格雷码
```

### 亚稳态 metastability
```
- 建立/保持时间违规 → 触发器输出不确定
- 不能消除，只能降低概率（打两拍）
- 打两拍后仍 X → 检查时钟关系/约束
```

### 异步 FIFO
```
- 读写不同时钟域
- 指针用格雷码 + 打拍同步
- 满/空判断（领先/滞后位）
```

### 布线局部性（硬件版局部性原理）

FPGA 也有"局部性"，比 CPU 更物理，方向相反：

```
软件局部性（优化，影响快慢）      FPGA 对应
──────────────                ──────────
空间局部性（附近数据一起用）  →  布线局部性（相关逻辑放近，走线短）
时间局部性（频繁一起用）      →  触发器/逻辑簇（同 always 的 reg 放同 CLB）
缓存预取（猜下一步碰哪）      →  nextpnr 布局布线优化（自动把相关逻辑放近）
```

**关键区别**：软件里局部性是性能优化（缓存没命中 → 慢一点）；FPGA 里布线局部性是**生死**（走线太长 → 时序不收敛 → 设计跑不到目标频率甚至综合失败）。

**你的影响手段**：
- 模块划分清晰 → 相关逻辑天然近
- 状态机编码、流水线深度 → 决定综合工具能不能布好
- nextpnr 干的就是"把相关逻辑物理放近"——硬件版缓存预取
