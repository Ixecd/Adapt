### 超前进位（加法器提速）
```
问题：普通加法器进位"串行传播"——每一位的进位要等前一位算完
      8 位加法 = 8 级进位串联 → 位数越多越慢（行波进位）

解法：超前进位（Carry Lookahead）——不等前一位进位，预判每一位要不要进位：
  两个信号（不看进位输入）：
    G（Generate 生成）：A_i & B_i → 这一位"一定产生进位"（两个1相加）
    P（Propagate 传播）：A_i | B_i → 这一位"会把进位传下去"（有1个1）
  进位：C_{i+1} = G_i | (P_i & C_i)，展开后只依赖"初始进位 + 各位G/P"
  → 所有位的进位同时算（并行），延迟从"N 级串行"降到"2-3 级"

代价：进位展开式越来越复杂 → 面积大
实际：4 位一组超前进位 + 组间串联（性能/面积折中）

和流水线同一哲学：找出"串行瓶颈"，用并行/预判摊平（空间换时间）
```

### 加法树 vs 行波（多个数求和，综合器替你优化）

```verilog
// 数 50 个信号里有几个高电平（popcount）
reg [5:0] cnt;
integer i;
always @* begin
    cnt = 0;
    for (i = 0; i < 50; i = i + 1)
        cnt = cnt + signals[i];
end
```

- **你的担忧**：for 看起来串行累加（50 个加法串起来）→ 慢
- **综合器的优化**：利用**加法结合律**（a+b+c 可重排），把串行链重排成**加法树**（两两相加，进位并行），延迟从 50 级串行降到 log2(50)≈6 级
- **关键**：慢不慢不是"是不是 1-bit 全加器"，是"**怎么连**"——行波串联（进位串行）慢、树形（进位并行）快，综合器选树形

**和超前进位的区别**：
```
超前进位 = 单个加法器"内部"进位并行（同一根加法器提速）
加法树 = 多个加法器"之间"树形并行（多个数求和提速）
→ 50 个信号求和是"加法树"，不是超前进位
```

**结论**：写高层（for 累加）让综合器优化成树形，比手写门级串联（行波）强——这是"RTL 能综合"的核心价值，也提醒你手写门级容易踩出行波瓶颈。


### 加法器写法（进位吸收）
```verilog
// 用拼接自动吸收进位，不用 if 手算
assign {C_OUT, SUM} = A + B + C_IN;
// 右边 9 位（A+B+C_IN 含进位），左边 {进位, 和} 也是 9 位 → 位宽对齐一次赋值
// 进位自动落 C_OUT，低 8 位落 SUM
```
