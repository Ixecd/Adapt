## others/ 选型与认知（预留位）

对应 Go 的 others。不是语法，是"什么时候用、为什么"的判断，最值钱。

### FPGA vs MCU
```
MCU  = 一个聪明人顺序处理（串行、灵活、改算法就是改代码）
FPGA = 一群专职工人同时干（并行、专一、改电路重新综合）
选型不是看谁厉害，是看活儿多大：
  4-6 路传感器 Hz~kHz 采样 → MCU 够
  几十通道 EEG + 实时解码   → 才需要并行
NVIDIA 的教训不是"选 GPU 弃 CPU"，而是"异构+按需"
```

### 系统设计才是地基
```
- 先软件思维把状态机/闭环/调度想清楚（架构）
- 再用 FPGA 做成并行电路（执行形态）
- 架构好 → 后期不返工（和软件架构同理）
```

### 脑机接口的演进
```
- 现在的活儿（闭环 tVNS）MCU 够，FPGA 是浪费
- 未来的活（多通道 EEG + 实时解码）才需要真并行引擎
- 别为明天的架构付今天的成本——现在留好接口/协议，到时换算力芯片
```

### 硬件学习曲线
```
- 踩坑存量决定速度（资深一周出原型，因为坑都踩过）
- FORGET.md 记录坑 = 把踩坑变成可复用的经验
- 软件人优势：状态机/解耦/调度思维 + 系统架构能力
```
