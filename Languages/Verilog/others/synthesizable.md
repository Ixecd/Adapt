## 可综合 Synthesizable

**可综合**：代码能被综合工具（yosys 等）翻译成**真实硬件电路**（门/触发器/布线）。FPGA 是真实电路，能造出来的只有逻辑门+触发器+连线——**凡是不对应真实硬件结构的写法，就不可综合**。

### 哪些可综合 / 不可综合

| 语句 | 可综合? | 为什么 |
|------|--------|--------|
| `always` | ✅ | 综合成组合逻辑或触发器（由敏感列表决定） |
| `begin-end` | ✅ | 语句分组，硬件天然支持 |
| `=` `<=` | ✅ | 组合逻辑 / 触发器 |
| `if-else` | ✅ | 多路选择器 MUX（硬件就是一堆选择器） |
| `case`/`casez`/`casex` | ✅ | 还是 MUX（x/z 按无关位处理） |
| `initial` | ❌ | 仿真初始化用，硬件上电没有"初始化代码" |
| `fork-join` | ❌ | 并行执行是仿真概念，硬件没有"进程并发" |
| `forever`/`repeat`/`while` | ❌ | 循环是仿真激励用，硬件没有"循环执行" |

### 核心判断标准

**能不能对应到真实的门/触发器/连线**：

```verilog
// 可综合：综合成真实电路
always @(posedge clk) cnt <= cnt + 1;   // → 触发器 + 加法器
assign y = sel ? a : b;                  // → MUX

// 不可综合：只能仿真用
initial #10 clk = 0;                     // → 仿真时钟初始化，硬件没有
forever #5 clk = ~clk;                   // → 仿真时钟生成，硬件没有
```

### 为什么硬件没有这些

```
软件世界                硬件世界
─────────             ─────────
循环执行              持续运转的时钟（没有"循环"，只有每拍都跑）
初始化代码            上电时寄存器是物理状态（没有"初始代码"）
进程并发             一切都是并行的（多个 always 天然并行）
```

硬件只有"持续运转的电路"——所以循环、初始化、并行进程这些"软件思维"的东西都不存在。只有能对应到 MUX/触发器/组合逻辑的写法才可综合。
