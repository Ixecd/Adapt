# Anim 双流水线

## 矛盾

```
完整八 Pass 管线 → 不可能在 1ms 内跑完。
但帧级参数依赖上一帧生理反馈 → 不能预编译。必须实时。
两件矛盾的事必须同时成立：安全校验必须完整 + 每帧必须实时。
```

解 = 双流水线。前台 FPGA 硬实时 + 后台离线预交织。物理隔离。互不抢占。

## 前台实时浅流水线

```
Session 运行中。每 1ms：

帧 N   DSIR → ESIR → 固件写入（DAC输出）→ 生理采集（ADC回读）→ 偏差计算
           ↑                                                        │
           └──────────── 闭环回读到下一帧 DSIR ──────────────────────┘

不走 Pass 0-5。不走 FSIR。不走 PSIR。
FSIR + PSIR 在 Session 启动时已完成并缓存。
DSIR + ESIR 下沉到 FPGA 门级逻辑执行——不是软件——是硬件。

1ms 硬实时。热路径极短。
```

## 后台离线预交织

```
设备空闲时（充电中、未佩戴）→ Feelings-Server 后台启动：

.anim 源码 → Pass 0-2 → Pass 5 → FSIR 缓存至设备本地

下次 Session 启动时：
    直接加载已缓存 FSIR。
    跳过解析 + 类型检查 + 静态安全检查。
    只需跑 Pass 3 + Pass 6-8。
    Session 启动延迟 < 100ms。

注意后台只跑到 FSIR——不碰 PSIR。
PSIR 需要 PBM。PBM 永不离设备。
```

## 为什么要隔离

```
合并方案：Session 启动 -> 现场跑 Pass 0-8 -> 延迟数秒。
    -> 第一个 session 被延迟劝退的用户不会再开第二个。

微服务方案：每个 Pass 拆成独立服务 -> RPC 通信 -> 每次序列化。
    -> 1ms 硬死线不等人。

双流水线 = 前台只有两层 IR + FPGA。后台有前面五层 Pass。
两条线不通信——前台只读后台写好的 FSIR 缓存。
没有 RPC。没有序列化。文件读写一次。
```

## 分支预测——帧级预判

```
CPU 分支预测器：猜下一条指令走哪条路。
Anim 帧预判器：  猜下一帧生理响应往哪个方向偏。

预测器输入    用户历史生理曲线。
预测对        ESIR 帧无缝衔接。
预测错        安全插桩接管——切回保守帧。不 panic。

预判器跑在 FPGA 上——训练数据（历史 HRV）永不离设备。
读寄存器 + 简单线性外推。1ms 内完成。
```
