## Rust 并发编程

安全高效地处理并发是Rust诞生的核心目标之一，最初就是为了解决大型系统（如浏览器引擎）的高并发、高负载问题。它通过语言层面的设计，在保证内存安全的同时，实现了接近C/C++的极致性能。

### 并发与并行的区别
很多人容易混淆这两个概念：
- **并发（Concurrent）**：程序的多个部分在**逻辑上**可以独立执行，它们可以交替运行在同一个CPU核心上（通过时间片轮转）
- **并行（Parallel）**：程序的多个部分在**物理上**同时运行在多个CPU核心上

并发是并行的基础，并行是并发在多核硬件上的一种实现形式。并发编程的目标是让程序能够同时处理多个独立的任务，无论底层硬件是否支持并行。

## 线程基础

线程是操作系统进行**调度执行**的基本单位。

- 进程是操作系统进行**资源分配**的基本单位，每个进程拥有独立的地址空间、文件描述符、信号处理等资源

- 一个进程可以包含多个线程，所有线程共享进程的资源

> 还记得我们之前聊过的Linux内核吗？在Linux眼里，进程和线程本质上都是同一个`struct task_struct`结构体，唯一的区别就是**资源共享的程度不同**——进程独享所有资源，线程共享父进程的资源。

并发编程会引入一系列经典问题：数据竞争、死锁、竞态条件等。不同语言解决这些问题的思路截然不同：

- Java、C#等语言依赖重量级运行时（如JVM）来管理线程和垃圾回收，虽然降低了开发门槛，但带来了额外的运行时开销和不可预测的停顿

- C/C++直接使用操作系统提供的原生线程，但语言本身和编译器不提供任何并发安全检查，所有问题都需要开发者手动保证，稍有不慎就会出现难以调试的bug

Rust走了第三条路：

- 它没有重量级运行时，也没有垃圾回收，所有并发安全检查都在**编译阶段**完成，运行时零开销

- 通过所有权、借用检查、类型系统等机制，将最常见的并发错误消灭在代码运行之前

- 但这并不意味着并发编程可以掉以轻心，死锁、逻辑竞态等问题仍然可能发生，需要开发者谨慎设计

### 创建线程

Rust标准库通过`std::thread::spawn`函数创建新线程：

```rust
use std::thread;
use std::time::Duration;

fn main() {
    // 创建一个新线程，参数是一个闭包（推荐写法）
    let handle = thread::spawn(|| {
        for i in 0..5 {
            println!("子线程打印: {}", i);
            thread::sleep(Duration::from_millis(1));
        }
    });

    // 主线程继续执行自己的任务
    for i in 0..3 {
        println!("主线程打印: {}", i);
        thread::sleep(Duration::from_millis(1));
    }

    // 等待子线程执行完毕
    handle.join().unwrap();
}
```

**关键说明**

1. **线程的生命周期**：所有线程都依附于主线程。如果主线程先结束，整个进程会立即终止，所有未完成的子线程都会被强制销毁。这就是为什么上面的例子需要调用`join`方法。
2. **join方法**：会阻塞当前线程，直到对应的子线程执行完毕。它返回一个`Result<T>`，如果子线程发生panic，`join`会返回`Err`，包含panic的信息。
3. **闭包的优势**：闭包可以捕获当前作用域的变量，比单独定义函数更灵活，是Rust中创建线程的惯用写法。

### move关键字：强制所有权转移

当我们想在子线程中使用主线程的变量时，必须使用`move`关键字：

```rust
use std::thread;

fn main() {
    let s = String::from("hello");

    // move强制闭包获取s的所有权
    let handle = thread::spawn(move || {
        println!("{}", s);
    });

    handle.join().unwrap();
}
```

**为什么需要move？**

闭包默认是**借用捕获**变量。如果不使用`move`，子线程会持有`s`的引用。但子线程的生命周期可能长于主线程，如果主线程先退出，`s`会被销毁，子线程就会出现**悬垂引用**，这是严重的内存安全问题。

`move`关键字强制闭包获取变量的所有权，将变量从主线程转移到子线程中，保证了内存安全。这是Rust所有权系统在并发编程中的核心应用。

> 注意：如果变量是`'static`生命周期的（如字符串字面量`"hello"`），不需要`move`也能编译，因为它的生命周期和整个程序一样长。

### 消息传递：通道（Channel）

Rust推崇**通过消息传递共享内存**，而不是通过共享内存传递消息。标准库提供了`std::sync::mpsc`（多生产者单消费者）通道来实现消息传递：

```rust
use std::thread;
use std::sync::mpsc;

fn main() {
    // 创建一个通道，返回发送者(tx)和接收者(rx)
    let (tx, rx) = mpsc::channel();

    // 创建子线程，发送消息
    thread::spawn(move || {
        let val = String::from("hi");
        tx.send(val).unwrap();
        // 发送后val的所有权已经转移到通道中，不能再使用
        // println!("{}", val); // 编译错误
    });

    // 主线程接收消息
    let received = rx.recv().unwrap();
    println!("收到消息: {}", received);
}
```

### 关键说明

1. **所有权转移**：`send`方法会将消息的所有权转移到通道中，保证同一时间只有一个线程拥有消息的所有权，从根本上避免了数据竞争。

2. **阻塞特性**：`recv`方法会阻塞当前线程，直到收到消息或者通道被关闭。如果不想阻塞，可以使用`try_recv`方法。

3. **多生产者**：可以通过克隆发送者`tx.clone()`来创建多个发送者，实现多线程向同一个通道发送消息。

---

## 总结

Rust并发编程的核心哲学是**"通过编译期检查保证并发安全"**。它不依赖运行时，也不要求开发者手动管理所有细节，而是通过所有权、借用检查等语言特性，将最常见的并发错误消灭在编译阶段。

这让我们可以在享受C/C++级别的性能的同时，写出安全、可靠的并发程序，这也是Rust在服务器端、嵌入式、系统编程等领域快速崛起的重要原因。
